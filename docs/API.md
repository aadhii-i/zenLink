# ShortLink API Documentation

The full interactive API reference is auto-generated by FastAPI and always
reflects the current code exactly:

-   **Swagger UI**: `http://localhost:8000/docs`
-   **ReDoc**: `http://localhost:8000/redoc`
-   **Raw OpenAPI schema**: `http://localhost:8000/api/v1/openapi.json`

This file summarizes the endpoint surface as it grows phase by phase — treat
the URLs above as the source of truth for exact request/response schemas.
See [SECURITY.md](./SECURITY.md) for the full security posture (what's
implemented and verified vs. known accepted risks).

## Conventions

-   All endpoints are versioned under `/api/v1`, **except** the redirect
    route itself (`GET /{short_code}`), which is deliberately at the root
    domain — a short link has to look like `short.link/abc123`, not
    `short.link/api/v1/urls/abc123`.
-   Authenticated endpoints expect `Authorization: Bearer <access_token>`.
-   Every endpoint is rate limited (`RATE_LIMIT_PER_MINUTE`, default
    60/min per client IP, Redis-backed); `/auth/register`, `/auth/login`,
    and `/auth/refresh` additionally carry a stricter
    `AUTH_RATE_LIMIT_PER_MINUTE` (default 5/min). Exceeding a limit
    returns `429` with `{ "success": false, "message": "Too many requests. Please try again later." }`.
-   Error responses are always shaped as:
    ```json
    { "success": false, "message": "...", "errors": [...] }
    ```
    (`errors` is only present for 422 validation failures.)

## Endpoints

### Health (Phase 1)

| Method | Path             | Auth | Description                             |
| ------ | ---------------- | ---- | ---------------------------------------- |
| GET    | `/api/v1/health` | No   | Checks API, database, and Redis liveness |

### Auth (Phase 2)

| Method | Path                | Auth | Description                                    |
| ------ | ------------------- | ---- | ----------------------------------------------- |
| POST   | `/api/v1/auth/register` | No   | Create an account. Returns the created user (no tokens). |
| POST   | `/api/v1/auth/login`    | No   | Exchange email + password for an access/refresh token pair. |
| POST   | `/api/v1/auth/refresh`  | No   | Exchange a refresh token for a new access/refresh pair (rotation). |
| GET    | `/api/v1/auth/me`       | Yes  | Get the authenticated user's profile. |
| PATCH  | `/api/v1/auth/me`       | Yes  | Update the authenticated user's profile (currently: `full_name`). |

**Password requirements**: minimum 8 characters, at least one uppercase letter, one lowercase letter, and one digit.

**Tokens**: access tokens expire after `ACCESS_TOKEN_EXPIRE_MINUTES` (default 24h); refresh tokens after `REFRESH_TOKEN_EXPIRE_MINUTES` (default 7d). Each refresh call issues a fresh pair. Tokens are stateless JWTs — a refresh token remains valid until its own expiry even after a newer one has been issued (no server-side revocation list yet). Blacklisting/rotation-with-invalidation is planned for Phase 6 alongside rate limiting.

### URLs (Phases 3–4)

| Method | Path                  | Auth | Description                              |
| ------ | --------------------- | ---- | ----------------------------------------- |
| POST   | `/api/v1/urls`        | Yes  | Create a short URL (random Base62 code, or a custom alias). |
| GET    | `/api/v1/urls/stats`  | Yes  | Aggregate counts for the current user: total/active/inactive URLs, total clicks. |
| GET    | `/api/v1/urls`        | Yes  | List the current user's URLs — search, filter, sort, paginate (see below). |
| GET    | `/api/v1/urls/{id}`   | Yes  | Get a single URL owned by the current user. |
| PATCH  | `/api/v1/urls/{id}`   | Yes  | Update `original_url` / `is_active` / `expires_at`. Only fields present in the request body are changed — `short_code` is not editable. |
| DELETE | `/api/v1/urls/{id}`   | Yes  | Delete a URL. `204` on success. |

**Ownership**: every `{id}` route 404s (not 403) for a URL owned by someone else — existence isn't confirmed either way.

**Custom alias**: 3–32 characters, letters/numbers/hyphens/underscores only. Returns `409` if already taken, `422` if it's a reserved word (`api`, `docs`, `redoc`, `openapi.json`, `health`, `favicon.ico`, `static`) or fails the format/length rules.

**Expiry**: `expires_at` is optional and must be in the future; naive datetimes (no timezone offset) are treated as UTC. Sending `expires_at: null` on an update clears an existing expiry.

**List query params**: `search` (matches `original_url` or `short_code`), `is_active` (bool), `sort_by` (`created_at` | `click_count` | `expires_at` | `original_url`, whitelisted server-side), `sort_order` (`asc` | `desc`), `page` (default 1), `page_size` (default 10, max 100). Response: `{ items, total, page, page_size, total_pages }`.

### Redirects (Phase 3)

| Method | Path            | Auth | Description                                |
| ------ | --------------- | ---- | ------------------------------------------- |
| GET    | `/{short_code}` | No   | 302 redirect to the original URL. Not under `/api/v1` — see Conventions above. |

Resolution is Redis-cache-first with a PostgreSQL fallback (`URL_CACHE_TTL_SECONDS`, default 300s — only active, non-expired URLs are cached; the cache entry is explicitly invalidated whenever the URL is updated or deleted, not just left to expire). Returns `404` if the code doesn't exist, `410` if the URL has been deactivated or has expired. Each successful redirect records a click (timestamp, IP, user-agent, referrer, plus browser/OS/device parsed from the user-agent at write time) asynchronously in the background, after the redirect has already been sent — a failure to record never affects the redirect itself.

### Analytics (Phase 5)

| Method | Path                          | Auth | Description                              |
| ------ | ----------------------------- | ---- | ----------------------------------------- |
| GET    | `/api/v1/analytics/overview`  | Yes  | Report across all of the current user's URLs. |
| GET    | `/api/v1/analytics/top-urls`  | Yes  | Top URLs by click count (`limit`, default 5, max 50). |
| GET    | `/api/v1/analytics/urls/{id}` | Yes  | Report scoped to a single owned URL (same shape as `/overview`). 404s for a URL you don't own. |

**Report shape** (`/overview` and `/urls/{id}`): `total_clicks`, `daily_clicks` (last `days` days, default 30, max 365 — `?days=`), `browsers`, `operating_systems`, `devices` (each a `[{label, count}]` breakdown, sorted descending, `"Unknown"` for unparseable user-agents), `referrers` (top 10 by domain, extracted from the referrer URL — grouping raw referrer strings directly would produce mostly-unique noise since they include full paths/query strings), `recent_clicks` (last 20 raw events).

**Browser/OS/device parsing** happens once, at click-recording time (not re-parsed per report request) — see `utils/user_agent_parser.py`. **Country/geo-IP is not implemented** — the spec marks it optional, and it would need either a bundled GeoIP database or a per-click network lookup that would slow down every redirect; left out rather than shipping a column that's always null.
